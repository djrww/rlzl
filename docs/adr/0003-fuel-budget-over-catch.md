# ADR-0003：以事前燃料預算取代事後錯誤捕捉

- **狀態**：Accepted
- **日期**：2026-09-09（記錄日期）
- **決策者**：專案作者
- **取代**：無

## Context

「自拓展到極限」隱含一個直覺設計：**跑到爆掉為止，然後接住錯誤，換更大的策略重試**。

實測證明這在 const-eval 中**不可能**：

- const-eval 沒有 `catch_unwind`。
- 觸頂時直接產生 `E0080`，這是**編譯錯誤**，不是可捕捉的執行期事件。
- 編譯已經失敗，沒有任何程式碼有機會執行「重試」邏輯。

## Decision

**改為事前燃料預算（fuel budget）+ 續傳（resume）。**

- `welzl_fueled` 接受燃料額度，用完即停並回傳「未完成 + 目前狀態」。
- `welzl_escalate` 在編譯期以遞增燃料反覆呼叫，直到完成。
- `MAX_SAFE_FUEL = 64`（實測安全上界），`DEFAULT_FUEL = 16`。
- `welzl_auto` 依點數自動選擇遞迴或迭代路徑。

**核心原則：永遠不要撞牆，而是在撞牆前就知道牆在哪。**

## Consequences

### 正面

- 自適應路徑把上限從 120 點推到 **500,000 點 = 4,166 倍**。
- 這個「事前規劃」思路後來被推廣成 Tier 0 `plan()`（ADR-0005），
  成為本專案相對於競品（如 `robust` crate）最明確的差異化能力。

### 負面

- 燃料額度是啟發式，非保證。
- 需要維護「可續傳的狀態」，實作複雜度高於直接遞迴。

### 被推翻的直覺

「燃料越少 → 續傳次數越多」是錯的。實測 fuel=1 → gens=1，fuel=48 → gens=2。
續傳次數由問題結構決定，非線性於燃料額度。
