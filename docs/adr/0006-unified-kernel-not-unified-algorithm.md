# ADR-0006：統一「引擎」而非統一「演算法」

- **狀態**：Accepted
- **日期**：2026-09-09（記錄日期）
- **決策者**：專案作者
- **取代**：無

## Context

專案累積了五個子系統：i128 精確謂詞、Delaunay/Voronoi、線段最近距離、
多邊形布爾、區間濾波。問題是能否整合進「同一個演算法／引擎」。

## Decision

**統一資料表示與謂詞，不統一控制流。** 實作為 `src/kernel.rs`。

被統一的三樣東西：

1. **同一個數域** —— i128 有理數（`Rat` / `RatPt` / `Circle`）
2. **同一套謂詞** —— 所有拓撲判定化約成原始座標的行列式
3. **同一條決策管線** —— Tier 0 規劃 → Tier 1 濾波 → Tier 2 精確

明確**不做**的事：把 Delaunay（分治／增量）、布爾（掃描線）、
最近距離（空間索引）合併成單一函式。三者控制流無共同結構。

依據是**次數不累積原則**：拓撲判定可化約成原始座標的行列式，
有理數頂點只在最終輸出出現。因此子系統共用謂詞就足夠，不需共用迴圈。
這與 CGAL「精確幾何核心 + 演算法層」的分層一致。

## Consequences

### 正面（已驗證，8 項測試）

- `precision_modes_agree`：Exact / Filtered / Auto 三種策略對 MEC 與 Delaunay
  給出**完全相同**結果。
- `predicate_dispatch_agrees`：20,000 組隨機資料，濾波與精確路徑零分歧。
- `preflight_catches_unsafe_coords`：C=1e6 對 MEC（次數 6）事前回報錯誤，
  對 orient2d（次數 2）放行。
- 跨算法**組合**可行且無精度損失：`closest_pair`（Delaunay → 最近點對，
  60 組隨機驗證等同暴力法）、`polygon_distance2`（布爾判定 + 線段距離）。

### 負面 —— 整合的硬邊界

跨算法**閉環**（A 的輸出當 B 的**輸入座標**）**第 1 輪就斷**。

實測：12 點（座標上界 100，7 bit）→ Delaunay → Voronoi 頂點 → 想再做 Delaunay：

```
round 1: 15 頂點 | max|num|=21 bit  max den=15 bit  共同分母 LCM=121 bit
   → 通分後座標溢位 i128 —— 閉環斷裂於 round 1
```

反直覺之處：15 個頂點**各自**的分母只有 `[6,6,6,7,8,8,10,11,12,12,13,13,13,14,15]` bit，
都很小。但要放進同一個整數座標系就必須通分，LCM 炸到 121 bit。

這不是實作缺陷，是有理數幾何的本質障礙
（Goodrich–Pollack–Sturmfels：某些點線排列在整數格上的實現必須有指數級位元複雜度）。

### 已知的繞道：snap rounding（有損）

每輪把有理頂點四捨五入回整數，可無限迭代，座標位元僅線性成長：

```
round 1:  24 頂點 → 24 相異點, 12 bit
round 2:  43 頂點 → 42 相異點, 15 bit
round 3:  79 頂點 → 79 相異點, 18 bit
round 4: 153 頂點 → 151 相異點, 21 bit
round 5: 297 頂點 → 292 相異點, 24 bit
round 6: 581 頂點 → 563 相異點, 25 bit
round 7: 1131 頂點 → 1083 相異點, 27 bit
```

代價是每輪引入 ≤0.5 誤差、拓撲可能改變（43→42、581→563 即為被合併掉的點）。
本專案**未採用** snap rounding，因為它違背「精確」的核心承諾；
若未來要支援迭代式細分（見 ROADMAP.md），必須明確標示為有損模式。

### 結論表

| 整合層級 | 可行性 |
|---|---|
| 共用謂詞與數域 | ✅ 已驗證 |
| 共用精度決策管線 | ✅ 已驗證 |
| 跨算法組合（輸出當查詢） | ✅ 已驗證 |
| 跨算法閉環（輸出當輸入座標） | ❌ 1 輪即斷 |

**「判定與構造分開」不只是建議，是整合可行性的邊界線。**
