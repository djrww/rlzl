# ADR-0001：以 i128 有理數作為唯一數域

- **狀態**：Accepted
- **日期**：2026-09-09（記錄日期，非決策發生日 —— 見 CHANGELOG.md「日期可信度」）
- **決策者**：專案作者
- **取代**：無

## Context

Welzl 最小包覆圓需要判定「點是否在圓內」。以 f64 實作時，
接近退化的組態（近共圓、近共線）會因災難性抵消得到錯誤的符號，
使演算法回傳非最小的圓，或在遞迴中不終止。

可選數值策略：

1. f64 + epsilon 容差
2. f64 + Shewchuk 自適應精度展開（adaptive precision expansion）
3. 任意精度有理數（bignum / GMP）
4. 定寬整數有理數（i128）

專案的第二個目標是「觸碰編譯期求值的極限」，因此數值核心必須能寫成 `const fn`。
這是硬約束：Rust 的 const-eval 不允許浮點運算的位元級可重現性假設，
也不允許在 const 上下文中配置堆積記憶體。

## Decision

**採用 i128 定寬整數有理數作為唯一數域。**

- 點座標為 `(i128, i128)` 整數。
- 圓以 `Circle { cx, cy, cd, r2 }` 表示，圓心是有理數 `(cx/cd, cy/cd)`，
  半徑保留為平方形式，不開根號。
- 所有判定（`in_circle`、`orient2d`、`incircle`）化約為整數行列式的符號。
- 全部核心函式標記為 `const fn`。

## Consequences

### 正面

- 判定結果**精確**，無 epsilon 調參，無退化組態誤判。
- 可在編譯期求值，達成專案第二目標。
- 無外部依賴、無堆積配置，`#![no_std]` 相容。
- i128 乘法實測 4.08 ns，僅為 f64 乘法（1.83 ns）的 2.2 倍 —— 代價可接受。

### 負面

- **座標範圍受限**。位元需求 ≈ `d·log2(C) + log2(terms) + 1`，其中 d 為謂詞次數。
  MEC 的 `circ3` 次數為 6，安全座標上界僅 ~5.2×10⁵。
- **半徑無法以精確值輸出**，只能比較平方；開根號會離開有理數域。
- **溢位是靜默的**。release 模式整數溢位為 wrapping，且 `-C debug-assertions`
  不跨 crate 邊界傳播（見 ADR-0004）。
- 無法表達超越數結果（球面面積 —— 見 APPLICABILITY.md）。

### 後續行動

- ADR-0002 處理「精確但範圍受限」與「可擴展」之間的張力。
- ADR-0004 處理靜默溢位的緩解。
