# ADR-0008：所有微基準測試強制使用 `black_box`

- **狀態**：Accepted
- **日期**：2026-09-09（記錄日期）
- **決策者**：專案作者
- **取代**：無

## Context

第一次量測區間濾波效能時，所有結果都是 **0.00 ns**。

原因：`-O` 下的 LLVM 發現計算結果未被使用，把整個迴圈消除了。
i128 謂詞全是純函式且無副作用，是死碼消除的完美目標。

若未察覺，會得出「區間濾波零成本」的結論 —— 與後續實測的
**0.23× 負收益**完全相反。

## Decision

1. **所有微基準必須以 `std::hint::black_box` 包住輸入與輸出。**
2. 任何回報「0 ns」或「快到不合理」的量測，**預設視為無效**，必須先檢查死碼消除。
3. **最佳化之前先做假設檢驗定位瓶頸**，不憑直覺。
   本專案正是靠這步發現瓶頸是型別轉換（`i128 as f64` 6.70 ns）
   而非整數算術（i128 orient2d 5.83 ns）—— 若憑直覺優化算術，方向完全錯誤。

## Consequences

### 正面

- 避免把作廢數據寫進文件。
- 「先假設檢驗再優化」成為專案慣例，直接促成 ADR-0005 的決策。

### 負面

- `black_box` 本身有微小開銷，會使絕對數字略微偏高。
  相對比較仍然有效，這是可接受的取捨。

### 相關教訓

**隨機取樣抓不到災難性抵消。** 600,000 組隨機測試與對稱測試案例
都無法暴露浮點誤差；必須用 Cassini 恆等式（`F(n+1)F(n-1) − F(n)² = ±1`）
這類刻意構造的病態輸入 —— 該構造下浮點 16 組誤判 6 組。
