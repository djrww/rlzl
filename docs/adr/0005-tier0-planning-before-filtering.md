# ADR-0005：Tier 0 事前規劃優先於區間濾波

- **狀態**：Accepted
- **日期**：2026-09-09（記錄日期）
- **決策者**：專案作者
- **取代**：無

## Context

教科書的精確幾何三層架構是：浮點濾波 → 區間算術 → 精確回退。
文獻普遍宣稱濾波帶來約 10× 加速。

本專案實作並量測後，得到**與文獻相反**的結果。

### 實測數據（含 `black_box`，rustc 1.98.1）

| 資料 | i128 精確 | 區間濾波 | 靜態誤差界 | 加速比 |
|---|---|---|---|---|
| orient2d 隨機 | 12.02 ns | 126.87 ns | 53.10 ns | **0.23×** |
| orient2d 共線 | 11.94 ns | 146.83 ns | 50.63 ns | 0.24× |
| incircle 隨機 | 23.47 ns | — | 58.97 ns | 0.40× |

### 假設檢驗定位瓶頸

| 操作 | 耗時 |
|---|---|
| `i128 as f64` 轉換 | **6.70 ns** |
| 整個 i128 orient2d | **5.83 ns** |
| `i64 as f64` 轉換 | 2.04 ns |
| i128 乘法 | 4.08 ns |
| f64 乘法 | 1.83 ns |

**單次型別轉換就比整個精確謂詞還貴。貴的是轉浮點，不是整數算術。**

文獻宣稱的 10× 是相對 GMP/MPFR 這類任意精度庫，不是相對 i128。

## Decision

1. **保留三層架構，但把 Tier 0「事前規劃」放在最前面**，
   且它是**唯一預設啟用**的一層。`plan()` 為 O(1)，不碰資料，可編譯期執行。
2. 區間濾波（Tier 1）**預設關閉**，僅在輸入本來就是 f64 時啟用
   （`orient2d_f64`，實測獲利 1.95–2.14×）。
3. 在文件中**明確記錄負收益**，不隱藏對自己不利的量測結果。

## Consequences

### 正面

- Tier 0 是本專案在競品中未見的能力。`robust` crate（1,200 萬下載）的模型是
  「跑了再說，反正保證正確」；本專案能在**跑之前**回答「需要幾位元、會不會溢位、該走哪條路」。
  這在有時間預算的系統（即時 CAD、雲端 API、認證環境）中有實際價值。
- 意外發現：區間算術靠 f64 的 ±308 位指數範圍，**救回了 i128 會靜默溢位的案例**
  （C=1e9 需 176 bit，`Rat::cmp` 靜默回錯誤值，`ratcmp_interval` 正確回 `Some(1)`）。
  **i128 提供精度，f64 提供動態範圍** —— 兩者互補而非替代。

### 負面

- 與教科書架構不一致，需要額外說明。
- Tier 1 程式碼保留但預設不用，是維護負擔。

### 濾波的可證明性質

100 萬組 orient2d + 10 萬組 incircle 驗證，**濾波錯誤 0 次**。
成功率只取決於退化程度，幾乎與座標量級無關：
均勻隨機 100.00%、近共線 99.21%、網格 99.22%、完全共線 9.39%。
最壞情況只退化成全走精確路徑，不會給錯答案。
