# ADR-0007：Delaunay 暫以 O(n⁴) 暴力法為準，移除未驗證的增量實作

- **狀態**：Accepted
- **日期**：2026-09-09（記錄日期）
- **決策者**：專案作者
- **取代**：無

## Context

`src/delaunay.rs` 曾包含一個 Bowyer–Watson 增量插入實作。它是錯的：

- 5×5 網格輸入產出 **1047 個三角形**（正確答案應為 32）
- 隨機測試 **僅 3/60 通過**

根因是空腔（cavity）邊界判定錯誤。這類錯誤的特徵是：
在均勻隨機資料上偶爾看起來正常，一遇到共圓／網格等退化組態就崩潰。

## Decision

1. **刪除該實作**，不修補。
2. 保留 `delaunay_brute(pts, strict)`（O(n⁴)）作為**預言（oracle）**。
3. 對外 API `delaunay` 目前走暴力法 —— 慢但正確。
4. 未來若需生產級效能，**從頭實作**並以 `delaunay_brute` 逐案比對，
   不重新引入舊程式碼。

## Consequences

### 正面

- 正確性有預言可驗證，`is_delaunay()` 可獨立檢查任何三角剖分。
- 避免了「看起來能跑但退化時錯」這類最難除錯的缺陷進入下游
  （Voronoi、`closest_pair` 都依賴它）。

### 負面

- **O(n⁴) 不可用於生產**。這是 ROADMAP.md Phase 7 的首要技術債。
- 點數規模受嚴重限制。

### 教訓

錯誤的快速演算法比正確的慢演算法糟糕得多，因為它的錯誤會靜默傳播到所有下游。
在有預言可比對之前，不要把效能最佳化的幾何演算法放進 API。
